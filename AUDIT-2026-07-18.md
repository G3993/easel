# Easel Full Audit — 2026-07-18

Six parallel audits (architecture, performance, stability/threading, memory/resources, testing/tooling, platform reach) over `~/easel` (66.5k lines) plus the surrounding ecosystem (`~/ShaderClaw3`, `~/easel-agent-sdk`, `easel-mobile*`, `shader-firestore-sync`). Every finding below was verified in code with file:line evidence by the auditing agent; this file is the condensed synthesis.

**Overall verdict:** the engine core is in better shape than its size suggests — resource management is unusually leak-hardened (RAII wrappers, bounded queues, pooled FBOs, async PBO readbacks all verified clean), and OSC/MIDI threading discipline is correct. The debt concentrates in five places: a 16.9k-line `Application.cpp` god object, one dominant fixed GPU cost that explains every sub-40fps report, crash-likely races in the default-on voice/mic paths, show-data integrity traps around save/load/undo, and four hand-written ISF hosts drifting apart — which is the real blocker to "compositing + shaders available everywhere."

---

## P0 — Show safety (fix before the next live set; ~1 week total)

1. **Speech-callback race (crash-likely, default ON).** Speech.framework's resultHandler mutates `m_voicePartial`, timeline keyframes, and `m_cueFeed` from its own queue while the render thread iterates them (`Application.cpp:3442-3481`, `3265-3358`; `MacSpeechRecognizer.mm:109-122`). `m_voiceContinuous` defaults true. Fix: callbacks append to a mutex-guarded queue, drained in the main loop next to `m_cueClient.poll()`. ~3h.
2. **`AudioAnalyzer::stopCapture()` races the detached init thread (crash-likely, push-to-talk).** `stopCapture` (`AudioAnalyzer.cpp:51-58`) skips the `m_initInFlight` guard the destructor uses; release PTT during the TCC permission wait → double-delete of `MacAudioState`. ~1h.
3. **Silent layer loss on project load + positional binding shift.** Missing media file → layer dropped with only a cerr (`Application.cpp:16143-16201, 16426-16428`); next save makes it permanent, and image bindings restore by index so every later binding lands on the wrong layer (`:16481-16490`). Fix: placeholder layer + relink UI; bind by layer id. ~1 day.
4. **Non-atomic save + throwing load.** Save writes the show file in place (`:15785-15792`) — crash mid-write truncates it. Load body has dozens of unguarded typed `json::get` calls that throw *after* the layer stack was cleared (`:15849, 15928, 16132`). Fix: tmp+rename; try/catch restoring a valid state. ~3h.
5. **Undo destroys layer identity.** `LayerSnapshot` omits `id`/`managedKey`/effects/masks (`UndoStack.h:11-35`); restore reassigns fresh ids → zone `visibleLayerIds` go black, DataBus bindings break, effect chains vanish. ~half day.
6. **WebSocket frame length unchecked (remote-triggerable abort).** 64-bit wire length → unclamped `resize` + int truncation in `EthereaClient.cpp:189-223` / `CueClient.cpp:189-216`; any LAN peer can kill the app mid-show. Clamp + try/catch. ~1h.
7. **Deleting a stalled live-stream layer freezes the app.** `VideoSource` destructor joins a decode thread stuck in `av_read_frame` with no `interrupt_callback` (`VideoSource.cpp:24-26, 375-386, 555`). ~half day — also unlocks #8.
8. **VRAM retention on long sets: undo pins sources with no `suspend()`.** `suspendOrphanedSources` is a no-op for Shader/Fluid/Fluid3D/Particle/Hologram sources (`ContentSource.h:16`); a deleted Fluid3D layer pins ~100 MB, multipass shaders up to 132 MB at 4K, ×50 undo entries. Add suspend/lazy-reinit overrides (pattern exists in `VideoSource.cpp:415-451`). ~1 day.

Smaller P0 adjacents: GL deletes from the closing thread with no context (`Application.cpp:1441-1479` / `NDIOutput.cpp:53-66`, split destroy into NDI vs GL halves); `[task cancel]` missing in MacSpeechRecognizer stop; SCK 2s-timeout delete-while-delivering (`AudioAnalyzer_mac.mm:336-344`); macOS disconnect stall (`#ifdef _WIN32` socket close should be unconditional); `std::stoi` on user-typed URLs; `etLog` static string race; SSE buffer cap.

## P1 — Performance: lock the 40fps floor at 4K (~1 week)

1. **The 35fps mystery is solved and it's mostly one thing:** the warp chain renders every zone into a 2× supersampled RGBA16F FBO (7680×4320 = 265 MB) and downsamples it **even when there is no warp at all** (`Application.cpp:2381-2477`) — ~900 MB/frame of bandwidth ≈ 5-9ms before any content. Fix: bypass the SS chain when the mapping is identity/absent. Small change, biggest single lever.
2. **Open Properties panel forces every zone to fully composite + SS-warp per frame** (`:2200-2213`) — 3-zone shows pay 3× for thumbnails. Throttle preview-only zones to ~10 Hz / low res / no SS.
3. **Redundant ping-pong clears** break render passes on GL-on-Metal (`CompositeEngine.cpp:467, 144-152, 696-699`) — drop the up-front clear.
4. **Uniform churn:** ~130 string-hashed uniform sets per pass per frame; text inputs heap-allocate per character per frame (`ShaderSource.cpp:753-953, 921`; `ShaderProgram.cpp:95-101`). Cache GLint locations per program. Main CPU-side win.
5. **Shader render-scale control (50/75%)** — per-layer `shaderWidth/Height` override already exists (`Application.cpp:1756-1768`); expose it as a user knob. Immediate recovery lever at 4K.
6. **Thumbnail generation compiles a full ISF shader every ~4 frames while the browser is open** — persist thumbs to disk (`~/.easel/thumbs/<hash>.png`) so compiles happen once ever.
7. **Autosave serializes the whole project on the main thread every 30s** (`:1036-1043`) — hand JSON build/write to a worker.
8. Small: auto-crop sync `glGetTexImage` stall; `enumerateMonitors()` ~5×/frame → cache + GLFW callback; per-frame screenshot-trigger `fs::exists`.

Verified already clean: NDI triple-PBO+fence, recorder double-PBO, projector fence sync, throttled shader watcher, event-driven audio hotplug, idle scratch release.

## P2 — Structure, tests, ops (~2 weeks; enables everything after)

1. **Delete ~2,900 lines of verified dead code** (never-called methods incl. `renderSplash`/`renderLandingPage`/`renderRightToolRail`/`renderVoiceCommandBar`, `#if 0` blocks, `if (false &&` tabs). Hours.
2. **Extract four seams from Application.cpp** (16,874 → ~8-9k lines, `renderUI` 5,201 → ~2,500): `OSCRouter` + managed-layer service (the agent-SDK control surface, ~1.1k lines, currently inside `renderUI`); `ShaderBrowserPanel` (~1.2k); `TimelinePanel` + transport (~3.6k); `ProjectSerializer` (~1.25k, makes round-trip tests possible). Move MIDI/OSC polling out of `renderUI` into `run()`.
3. **Wire tests into reality:** CTest currently discovers only `test_scanning`; CI runs 1 of 4 real suites; `test_shaders` (the key gate) never runs automatically. Hoist `include(CTest)`, register all Catch2 targets, add `ctest` + `test_shaders` to CI. ~2h.
4. **Write the 3 highest-value tests:** project save/load round-trip + degraded-load fixtures; UndoStack identity preservation (fails today — that's the point); warp math (`HomographyUtils::solve` identity/round-trip/degenerate). ~2-3 days total.
5. **Observability:** ~480 raw cout/cerr, no levels/timestamps, no crash handler; shader compile failure at showtime is invisible (stderr + `/tmp/etherea_debug.log` only) and pollutes undo before validating. Minimal Log:: + set_terminate/backtrace + an error toast. ~1.5 days.
6. **Build hygiene:** no `-Wall`, no default `CMAKE_BUILD_TYPE` (documented local flow builds unoptimized -O0 for a 40fps app!), GLFW/stb/ImGui fetched from moving branches — pin SHAs, default Release. ~half day + warning cleanup.
7. Consolidate: 35 static-local UI states → panel members with `reset()` on project load; manifest read-modify-write ×3 → `ShaderClawBridge::load/saveManifest`; 7 hand-rolled pill-button lambdas → shared widget helpers; 6 hand-rolled key-chord handlers → one shortcuts table.

## P3 — "Available everywhere" (the product goal; 3 milestones, ~6-8 weeks)

Reality: one shader corpus, **four hand-written hosts** (C++ `ShaderSource.cpp`, WebGL `isf.js`/`renderer.js`, a third stripped host in the mobile bundle, Python metadata parser in the SDK), no executable contract. Compositing is desktop-only in any real sense (web = fixed 4-slot, 5-blend-mode shader; its 7-layer model is dead code never loaded). Audio bus has a canonical schema but only Python is generated from it — drift has already shipped (`audioLevelPresence` desktop-only; mobile fakes `audioBassTime` with wrong semantics; web still contains the multipass swap bug the C++ host fixed and documented). Web preview also *mutates* shaders (injected spotlight/video-mix/transparency), so web QA ≠ desktop output.

- **M1 — One contract (~1-2 weeks):** write the EaselISF dialect spec + golden conformance corpus (event inputs, text, .vs, sized/persistent passes, every audio uniform); run it through both existing harnesses (`test_shaders` offscreen GL + `eval_harness.cjs` headless Chrome); fix the web swap rule (3 lines); extend `gen_audio_bus.py` to emit the C++ preamble, JS `AUDIO_BUS_FLOATS`, and Swift enum. Kills the whole drift class.
- **M2 — One catalog (~1 week, mostly unblocking):** firebase login + service key → the already-built `~/shader-firestore-sync` daemon goes live → SDK, web, and mobile read one Firestore catalog with `snap_shader.cjs` thumbnails; deletes the hand-run `sync_mobile_bundle.cjs`/RAIL duplication.
- **M3 — One compositor (~3-4 weeks):** define the composition document (ordered layers × {shaderRef|imageRef, 12 blend modes, opacity, transform, visible} + audio bus, anchored on the SDK's existing scene/zone schemas); implement as an N-layer loop in the web compositor; extract `EaselCore` (frame loop + LayerStack/CompositeEngine + zones + OSC + deserialize — the engine is already ImGui-free, only Application.cpp entangles it) so one binary serves the ImGui app AND an `easel-headless` render node for house installs. Exit test: the same saved composition renders on desktop, web, and headless from one JSON.

### Suggested sequencing

Week 1: P0 (show safety). Week 2: P1 items 1-5 (the 60fps@4K lock) + P2 item 1 (dead code) + item 3 (CI wiring). Weeks 3-4: P2 extractions + top-3 tests + observability, and start P3-M1 in parallel (it's spec work, mostly independent). Then M2 (needs only credentials) and M3.

The P2 extractions and P3-M3 converge: `ProjectSerializer` + `OSCRouter` + `EaselCore` are the same architectural direction — every hour spent there pays into both maintainability and the headless/everywhere goal.
