### Projector / NDI crash fix (the live issue)
- **Root cause (confirmed from crash reports `~/Library/Logs/DiagnosticReports/Easel-*.ips`):** every crash is `abort()` → `__assert_rtn` → `_glfwInputWindowContentScale` (asserts content scale > 0) → fired from `viewDidChangeBackingProperties` during a **macOS native fullscreen EXIT transition** (`_NSExitFullScreenTransitionController`). i.e. opening/switching a projector (or an NDI receiver connecting → a window/display event) kicks the editor out of native green-button fullscreen, GLFW asserts on the transient 0 backing scale, hard SIGABRT. NOT a catchable ObjC exception.
- **Fix applied:** `disableNativeFullscreen(GLFWwindow*)` added in `ProjectorOutput_mac.mm` (sets `NSWindowCollectionBehaviorFullScreenNone`); called on the **editor** window in `Application::init` (after `EaselMac_UnifyTitleBar`) and the **projector** window (via `makeWindowTrulyBorderless`, which now also uses FullScreenNone instead of FullScreenAuxiliary). Verified `disableNativeFullscreen` symbol is in the built binary.
- Also: `presentOutputs()` glFinish gated to projector-output-only + destroy-stale-projectors-before-create pre-pass. **NOTE:** the last re-apply of the presentOutputs edit may NOT have landed (an Edit failed on a staleness guard near the end of the session) — **verify `presentOutputs` in Application.cpp** has the `needsSync`/`disableNativeFullscreen`/pre-pass; if not, the original unconditional `glFinish()` is harmless but the destroy-before-create pre-pass should be re-added.
