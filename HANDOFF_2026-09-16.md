### Two real bugs fixed (not just layout)
1. **The red border + tooltip "bug" the user kept seeing** — this was genuinely Dear
   ImGui's own built-in error-recovery indicator (`io.ConfigErrorRecoveryEnableTooltip`,
   default on in this ImGui version), not a rendering glitch or an NVIDIA overlay (that
   was a wrong guess earlier in the session — don't repeat it). Root cause: a trailing
   `SetCursorScreenPos()` at the very end of `renderShowDeck()` with no item submitted
   after it, which Dear ImGui 1.92 flags every frame. Found it by temporarily hooking
   `ImGuiContext::ErrorCallback` in `UIManager::init()` to print to stderr (that
   technique is worth remembering — much faster than screenshot-guessing for ImGui
   layout bugs). Fixed with a `Dummy({0,0})` per ImGui's own documented fix; diagnostic
   hook was added and then removed in the same session (net diff on `UIManager.cpp` is
   zero — don't be surprised it's not in `git status`).
2. **MIDI hot-plug on Windows was fully broken** — `MIDIManager::handleHotplug()` was a
   literal no-op on Windows (comment said "no topology tracking yet"). Unplugging the
   controller left stale `HMIDIIN` handles open forever; replugging did nothing until
   the app restarted. Fixed in `MIDIManager.cpp`/`.h`: `handleHotplug()` now polls
   `listDevices()` every frame and compares against a cached list; on any change while
   something's open, it calls `closeDevice()`. The **existing** app-level auto-reconnect
   in `Application.cpp` (~line 4010, polls every ~1s for "nothing open, user hasn't
   picked None") then picks a fresh connection back up automatically. Also had to start
   actually recording `m_deviceName` in `openDevice()`'s single-device Windows path (it
   was declared but never set) — not currently used by the new hotplug logic (which
   always falls back to "all devices" via the existing auto-reconnect) but there in case
   a future pass wants to restore the user's exact single-device pick after a hotplug.
   **Not tested with real hardware this session** — logic was reasoned through
   carefully but the user should verify unplug/replug and swap-for-a-different-
   controller actually behave before trusting it fully.
